# Установка и запуск MultiParser (Windows)

> **Статус:** инструкция подготовлена по исходникам и зависимостям. Она не является результатом успешного тестирования на чистой Windows: финальная сборка и полноценный smoke-test отсутствуют.

## Требования

- Windows 10/11, PowerShell и установленный Git.
- Python 3.12 x64 для первоначального запуска. Совместимость конкретных версий зависимостей и Python следует проверить на своей системе.
- Доступ в интернет для установки пакетов и браузеров.
- При использовании антикапчи, Telegram или платных прокси нужны собственные учётные данные; без них запуск интерфейса возможен.

## Установка из исходников

В PowerShell выполните команды **по порядку**:

```powershell
git clone https://github.com/The88788/MultiParser.git
cd MultiParser
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
```

Если используете стратегию `patchright`, попробуйте дополнительно:

```powershell
.\.venv\Scripts\python.exe -m patchright install chromium
```

Некоторые другие стратегии, включая Camoufox, могут требовать собственной установки/загрузки браузера. См. документацию соответствующей библиотеки. Если возникают конфликты зависимостей, сначала проверьте версии Python, Qt и браузерных пакетов; не считайте текущий `requirements.txt` гарантированно воспроизводимым lockfile.

## Запуск

Wildberries:
```powershell
.\.venv\Scripts\python.exe main_wb.py
```

Ozon:
```powershell
.\.venv\Scripts\python.exe main_ozon.py
```

Скрипты запускают **два отдельных окна приложений**, а не универсальное окно с выбором магазина.

При первом запуске создаются `config_wb.json` или `config_ozon.json` на основе `config_*.default.json`. Локальные конфиги игнорируются Git; вводите параметры через интерфейс. Директории `logs/`, `output/`, `proxies/`, `profiles/` также используются во время работы.

## Настройка секретов

Используйте **один** из двух способов:

1. Введите ключи и токены в соответствующих полях GUI. Они будут сохранены в локальном JSON-конфиге без шифрования. Не загружайте такие файлы в Git и не передавайте третьим лицам.
2. Скопируйте `.env.example` в `.env` и заполните нужные поля. Эти значения применяются при запуске и имеют приоритет над локальными JSON-значениями только для известных секретных полей; уже открытое GUI может впоследствии сохранить их в локальном JSON. `.env` не является защищённым хранилищем.

```powershell
Copy-Item .env.example .env
notepad .env
```

Переменные начинаются с `MULTIPARSER_WB_` либо `MULTIPARSER_OZON_`. Например `MULTIPARSER_WB_CAPSOLVER_API_KEY`, `MULTIPARSER_OZON_2CAPTCHA_API_KEY`, `MULTIPARSER_WB_TELEGRAM_BOT_TOKEN`. Полный список в `.env.example`.

`config_*.default.json` должны оставаться без ключей. Удаляйте из рабочих копий/логов персональные данные перед публикацией issue.

## Экспорт и диагностика

Результаты Excel записываются в `output/`, логи в `logs/`. Точная работоспособность парсинга зависит от текущей структуры сайтов, защиты, браузерных стратегий, настроек прокси и лимитов провайдеров.

При ошибках проверьте: версию Python, успешность `pip install`, скачан ли Chromium, установлен ли Chrome/Edge для выбранной стратегии, содержимое лога **без секретов**.

## Сборка EXE: экспериментальная

В репозитории есть `main_wb.spec` и `main_ozon.spec`, но **проверенной сборки приложения нет**. Для эксперимента на Windows можно попробовать:

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\.venv\Scripts\python.exe -m PyInstaller main_wb.spec
.\.venv\Scripts\python.exe -m PyInstaller main_ozon.spec
```

Понадобится отдельно протестировать включение браузерных бинарников, работу установленных модулей, иконок и локальных конфигов. Не распространяйте полученные EXE как проверенный релиз до тестов на чистой системе.
